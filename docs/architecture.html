Factory Inventory Management — System Architecture

Full-stack demo application: Vue 3 frontend, Python FastAPI backend, in-memory JSON mock data (no database). This page summarizes the tech stack, request/data flow, and API surface.

Tech Stack

Frontend

localhost:3000
  • Vue 3.4 (Composition API)
  • Vite 5 build tool / dev server
  • vue-router 4 (history mode)
  • Axios for HTTP calls
  • Hand-rolled SVG charts, no chart library
  • Views, components, composables, i18n locales
↔
HTTP / JSON
REST over Axios

Backend

localhost:8001
  • Python FastAPI (>=0.110)
  • Uvicorn ASGI server
  • Pydantic 2 (response validation)
  • CORS middleware (open, dev-only config)
  • In-memory data — no database
  • Managed with uv
Data source: JSON files in server/data/ Testing: pytest + FastAPI TestClient i18n: English / Japanese

Data Flow

1
Filter interaction User adjusts Time Period, Warehouse, Category or Status in FilterBar.vue, updating shared state in the useFilters composable.
→
2
api.js View calls the matching api.js method; query params are built from getCurrentFilters() via Axios.
→
3
FastAPI route Route in main.py receives query params (warehouse, category, status, month).
→
4
In-memory filtering apply_filters() / filter_by_month() scan lists loaded at import time from server/data/*.json by mock_data.py.
→
5
Pydantic validation Response shaped and typed via response_model before serialization to JSON.
→
6
Vue refs & computed Raw response stored in a ref (e.g. allOrders); computed properties derive display-ready data for the template.

Notes & Known Gaps

Frontend calls with no backend route api.js defines task and purchase-order endpoints (/api/tasks*, /api/purchase-orders*) that have no matching route in main.py — these calls would 404 today.
Backlog view not routed Backlog.vue exists but is not registered in vue-router; it is reached via modal/embedded flows rather than direct navigation.
Filters don't apply everywhere Demand, Backlog and all Spending endpoints accept no query filters, so changing filters on those views won't affect the data returned.
Dev-only CORS CORS middleware allows all origins/methods/headers — appropriate for local demo use, not production.
